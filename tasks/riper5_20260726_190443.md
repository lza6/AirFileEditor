### 1.2 代码分析
- **MVI 架构基础**：`ReplacingViewModel` 在 `app` 模块订阅了任务进度（`repository.getTaskProgress()`）和 APM 性能指标（`MetricCollector`）。它将这些更新流映射到 `ReplacingState`，UI（Compose/View混合）再读取此状态。它处理的事件包含：`StartReplace`, `CancelReplace`, `RetryReplace`, `DismissTaskResult`, `PauseReplace` 等。
- **仓储层实现**：`ConfigRepositoryImpl` 在 `data` 模块中实现。它整合了 `shizukuManager`、`patchManager` 和 `mainPackManager`。主要的文件替换操作（`startReplace`）是通过启动后台 WorkManager 任务 `FileReplaceWorkerV2` 完成的。
- **文件替换机制**：`FileReplaceWorkerV2` 是一个后台 `CoroutineWorker`，在启动时检测最佳访问模式（ROOT, SHIZUKU, NATIVE），并创建对应的 `FileReplaceOrchestrator`（`RootCopyOrchestrator`, `ShizukuCopyOrchestrator`, `NormalCopyOrchestrator`）来实际执行复制和权限环境检测。
- **数据流与路径常量**：`PathConstants` 是核心路径中转不变量。它提供了安全的子路径规范化（防止路径穿越 `..`），包名校验正则以及应用私有 data/obb 目录在不同访问模式下的映射逻辑（如 `resolveTargetFile`）。

### 1.3 架构分析
- **当前物理拓扑**：
  - `:app` -> 依赖 `:domain` 和 `:core`，负责 UI（MVI + Compose + View）与 Shell 包装。
  - `:core` -> 依赖 `:domain`（部分非直接，底层通过 repository 提供），包含 WorkManager 替换引擎、三种模式编排器、NIO IO 优化器和权限 checker。
  - `:data` -> 依赖 `:domain` 和 `:core`，实现 `ConfigRepository` 接口，并提供 DataStore 数据存储及替换历史管理。
  - `:domain` -> 抽象逻辑层，包含核心业务实体模型、Repository 接口定义和业务 UseCase（不依赖 Android SDK，纯 Kotlin）。
- **技术栈现状**：Android SDK minSdk=26，Kotlin 2.0.21，Jetpack Compose & Material 3，WorkManager（CoroutineWorker），AIDL（Shizuku 跨进程通讯），Zip4j 与 Apache Commons Compress 解压，Preferences DataStore 数据流。

## 2. 方案探索
### 2.1 方案列表
- **方案 A：传统架构稳固与闭环收敛（V13.0.0 标准版）**
  - **概述**：基于现有架构（WorkManager + MVI + Shizuku/Root/Normal Orchestrator）进行漏洞治理与闭环收敛。重点修复 WorkManager 取消机制失效、目标身份空值兜底、解压路径 Zip Slip 安全漏洞。将已有的备份（`BackupManager`）和历史（`ReplaceHistoryManager`）接入核心替换事务。
  - **特点**：不做颠覆性架构修改，以安全、稳定、完备性交付为唯一目标。
- **方案 B：自适应防御与性能双引擎（V13.0.0 增强版）**
  - **概述**：在方案 A 闭环基础上，引入先进的时间伪造与隐匿机制（Phantom Stealth 2.0，基于正态分布规律拟合随机文件时间序列）；基于 mmap NIO 2.0 优化大文件映射；增加特权 IPC 白名单防御层，重构 Shizuku AIDL 接口，彻底删除 shell 命令行公共入口，防范越权攻击。
  - **特点**：性能与隐匿安全并重，适合对防封和极致 IO 吞吐有严苛要求的场景。
- **方案 C：端侧智能 AI 文件助理与跨平台融合（V14/V15 概念创新版）**
  - **概述**：超前引入 KMP 跨平台内核，将核心文件操作抽取为 KMP common 库，未来可直接移植到 iOS/PC 等平台。集成端侧轻量级大模型（如 On-Device LLM），使用自然语言通过 UseCase 进行智能解压、匹配、替换和时间混淆，提供极低门槛的智能文件助理 UI/UX。
  - **特点**：前沿技术探索，具备极强的可衍生性，但当前开发成本极高，受设备环境制约明显。

## 3. 执行计划
### 3.1 选定方案
**选定方案：方案 B（自适应防御与性能双引擎 - V13.0.0 增强版）**
- **理由**：该方案能以最合理的工程成本，直接解决 P0 级严重隐患（如路径穿越、命令注入、空身份覆盖和取消任务挂起），并大幅增强性能（mmap NIO 2.0 映射、小文件合并）和隐匿防护（正态分布随机时间戳拟合、Shizuku 特权接口白名单化）。这使得新版本（V13.0.0）能为用户提供“秒级、极速、无痛且安全”的体验。

### 3.2 步骤分解
我将优化升级计划拆解为 10 个核心原子模块改进步骤：

1. **[工程基线] 建立稳定可测试的构建基准**
   - 涉及文件：`.github/workflows/ci.yml`、`gradle/wrapper/gradle-wrapper.properties`。
   - 目标：定义一致的 Gradle wrapper 版本与 JDK 版本配置，消除 CI/CD 与本地开发的分歧，确保 100% 可构建及单测回归。
2. **[生命周期] 统一 WorkManager 后台任务状态机与幂等**
   - 涉及文件：`ConfigRepositoryImpl.kt`、`FileReplaceWorkerV2.kt`、`ReplacingViewModel.kt`。
   - 目标：将 ViewModel 内存取消动作直接与 WorkManager 的取消挂钩；给替换工作流引入基于 `targetPackage` 的唯一任务（KEEP/REPLACE）控制；失败时将错误原因完全写入进度管理器。
3. **[身份模型] 限制空身份与包名漂移不变量**
   - 涉及文件：`PathConstants.kt`、`MainActivity.kt`、`ReplacingState.kt`。
   - 目标：引入包装类型 `TargetPackage` 与 `TargetLocation` 替换零散的 String，主包扫描、替换复制、环境校验一律传递该模型，拦截 UI 回调处的空字符串漏洞。
4. **[解压安全] 统一防路径穿越 (Zip Slip) 安全解压机制**
   - 涉及文件：`ExtractManager.kt`、`ArchiveManager.kt`、`UniversalExtractor.kt`、`InputValidator.kt`。
   - 目标：收敛 3 个解压工具类为单一 `SafeArchiveExtractor`；所有解压条目解压时一律先作 canonical 绝对路径比对，确保不能写出缓存目录；记录相对文件树拓扑。
5. **[数据保护] 接入替换前备份与部分失败回滚事务**
   - 涉及文件：`BackupManager.kt`、`FileReplaceWorkerV2.kt`、`RootCopyOrchestrator.kt` 等。
   - 目标：把 `BackupManager` 正式串接到 `FileReplaceWorkerV2` 复制之前。成功时清除备份；遇到写入失败（如磁盘满、Binder 断连）时自动根据备份恢复，并在 `ReplaceHistoryManager` 记录完整的事务审计历史。
6. **[安全防护] 收敛 Shizuku AIDL 特权 shell 通道**
   - 涉及文件：`IFileOperationService.aidl`、`FileOperationService.kt`。
   - 目标：完全删除 `executeCommand` 和 `executeCommandWithOutput` IPC 接口，以防客户端通过 AIDL 执行任意 shell 提权；改用高度收敛的 `copyFile`、`deleteDir`、`killPackage` 等白名单强类型接口。
7. **[算法对抗] 拟合正态分布的伪造时间指纹算法**
   - 涉及文件：`FileTimeModifier.kt`、`TemporalSignatureManager.kt`（新）。
   - 目标：不使用机械的统一修改时间（如 1000L），升级设计“正态分布拟合时间掩饰”算法。扫描系统中其他正常 App 目录下文件的修改时间间隔，拟合出高仿真时间指纹，批量修改被替换文件。
8. **[极致性能] 内存映射 NIO 2.0 零拷贝写入与小文件合并**
   - 涉及文件：`IoOptimizer.kt`、各 `CopyOrchestrator.kt`。
   - 目标：大文件（>10MB）使用 FileChannel mmap 零拷贝写入；极小文件（<1KB）在内存中批量打包，减少系统调用次数和 Shizuku Binder 往返延迟。
9. **[信任升级] OTA 包信任校验与升级断点续传**
   - 涉及文件：`UpdateManager.kt`、`AppInstaller.kt`。
   - 目标：重构 OTA 下载完整性检查（正确解析 HTTP 206 断点数据）；添加更新包签名证书指纹（Fingerprint）静态对比；修补 `AppInstaller` 启动安装 Intent 被拒抛异常仍返回 success 的假结果缺陷。
10. **[UI/UX与无障碍] 任务 Overlay 可退性与错误事件一次性通知**
    - 涉及文件：`MainActivity.kt`、`Organisms.kt`、`ReplacingViewModel.kt`。
    - 目标：成功和失败状态下允许用户关闭全屏 Overlay；将“Toast 提示”和“弹出 dialog”由普通 State 转移成 Compose 的 `SharedFlow` 一次性事件，彻底避免配置重建（如旋屏）时重复弹出历史错误；完善主要组件触控目标与语义 contentDescription 描述。
