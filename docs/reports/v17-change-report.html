七、关键设计决策

  • 分块 mmap 阈值：64MB/块 + 2GB 上限走 channelCopy — 平衡映射虚存与 syscall 次数；2GB 以上 mmap 收益有限且内存风险高。
  • 内存水位注入方式：Worker 任务前 refreshMemoryPressure 一次性刷新 + IoEngine 内部 @Volatile 状态 — 避免每次复制都读 ActivityManager（性能），又不失动态性。
  • 单包边界校验：isSafeTargetPathForPackage 用 canonicalPath 解析 symlink 后收窄前缀 — 比笼统 data|obb 前缀更精确，横向越权写他包目录被拒。
  • 压缩炸弹口径：仅在解压总量 ≥512MB 时检查压缩率（避免小文件误判），条目数恒上限 10 万。
  • MVI 最小化：删 Intent 而非补假实现 — 保持契约与真实能力一致，避免"有按钮无能力"。

十一、已知限制与剩余风险

  • verify 待补：data/obb 目标目录 rename-then-delete 原子性未在 JVM 层单测覆盖（走 Shell Orchestrator 真实链路），已披露为待验证。
  • validateBomb 口径：对未压缩 TAR 压缩率恒≈1 不触发，压缩率维度仅对 zip/7z 有效；tar 类依赖条目数+总量（16GB）上限。
  • E2E 三态：模拟器无 Root/Shizuku 服务连接，故 Root/Shizuku 的真实复制链路未在设备端实测，仅验证了 fail-closed 与权限判定逻辑。
  • SmallFileBatchWriter：独立组件已测试但未接入 fastCopy 小文件分支（现有 Native 复制用 partition+batchFiles 等效），属能力预留。

十二、使用者与维护者须知

  • 构建/测试/门禁：.\gradlew.bat testDebugUnitTest :domain:test :data:testDebugUnitTest checkQuality assembleDebug
  • 新加安全能力：所有解压路径（ExtractManager/UniversalExtractor/ArchiveManager）必须先过 ArchiveSafetyGuard 再写 staging。
  • 复制路径必须过 isSafeTargetPathForPackage(path, targetPackage)（canonicalPath 解析），不要再退回到笼统 data|obb 前缀。
  • 内存水位在 Worker 任务前自动刷新；若新增非 Worker 的 IO 入口，需同步调用 IoEngine.refreshMemoryPressure。
